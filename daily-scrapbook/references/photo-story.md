# 照片解析与叙事编辑

## 照片台账

每张记录：`ID / 原路径或附件顺序 / 可见主体和动作 / 用户补充事实 / 未确认信息 / 主图或细节用途 / 裁切保护区域 / 抠图候选`。不必把完整台账发给用户。

看清横竖比例、表情与动作，辨认相近连拍。主图先考虑故事价值，不只选背景漂亮的一张。不自动从 EXIF/GPS 加入用户未要求公开的位置和时间。不要根据外貌判断关系、年龄或身份；人物对应不明而不影响内容时用中性描述。

## 叙事路线

- 过程：用户确认的准备、行动、结果。
- 片段：顺序不明时按吃饭、散步、阅读等内容分组。
- 主题：一本书、一只宠物、一次咖啡、手作等，靠主次和批注组织。
- 情绪：用户明确说的感受，由主图承接，其他图解释背景。
- 纪念：生日或成长节点等，只使用已确认的日期、年龄和关系。

文件顺序不等于时间顺序；光线不证明时刻。没有时间信息的日常页完全成立。

## 文案边界

允许压缩、改语序、断句、修正口误和描述可见内容。不虚构“第一次”、评分、价格、时间、地名、台词、心理活动和关系。照片不承载因果：“孩子在画画”不能扩成“她说这是送给妈妈的礼物”。

用户只说“周末吃饭散步”，标题可为“周末碎片”，不擅写“杭州一日游”。四张食物照不能变成“做了三个小时，大家都说好吃”。

## 三层文字

1. 短标题，通常 4—10 字；具体而自然，不强制“治愈”“松弛”。
2. 图旁批注，通常每图 8—22 字；指向具体动作或物件。
3. 可选收尾；无用户感受时不硬加人生总结。

日期有依据才出现。长文优先压成局部短句，保留用户强调的原话；一页放不下拆页。保留用户口语，不统一成亲子语气。

示例：用户“周末和朋友吃面，后来随便逛了逛，看到一只猫，挺开心。”

- 标题：“周末随便逛逛”
- 面条图：“先吃一碗面。”
- 街景图：“吃完就在附近走走。”
- 猫图：“路上遇到的小家伙。”
- 收尾可为“和朋友待着就很开心。”，感受与朋友关系来自用户；没拍到朋友不能补画进去。

## 数量处理

| 输入 | 行为 |
|---|---|
| 0 张 | 先查用户指向的可访问来源；确实没有则请求照片，不假装分析 |
| 1—2 张 | 做少图主视觉或有依据的局部细节，不伪造 4 个事件；用户坚持 4 个不同来源则还需补图 |
| 3—4 张 | 一页优先，全部保留，用主图、场景、物件分工 |
| 5—8 张 | 默认全部保留。先评估一页，必要时告知建议的 1—2 页分配和理由；一页要求优先，不自行拆页或减图 |
| 更多 | 全部编号后按事件分组，制作前给建议页数与每页分配。已允许多页时告知后执行；指定一页而有冲突时给一页与拆页建议 |

输入清点和成图覆盖是两件事：记录 N 张来源及每个 P 编号最终出现的位置。不能把一个抠图重复两次当成覆盖两张原照。若建议省略，先说哪张、为什么以及替代方案，用户未明确同意前保留该图。

## 最小页面计划

保存 `page-plan.md`：主题；用户明确事实；画面可见内容；省略的未知信息；P1—Pn 原照片映射及最终覆盖位置；裁切约束；页数与事前告知；如有省略则记录具体编号和用户同意依据；版式、配色、花字和小贴纸；最终文字；实际输入顺序；提示词；输出与检查。无需复制完整私人叙述或多份原图。
