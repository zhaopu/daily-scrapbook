# 手帐式 Plog

把用户的生活素材编成有观看顺序、有个人语气的照片日记。默认交付 **3:4 竖版、铺满画布的平面手账 PNG**；不额外画桌面、本子外观或拍摄道具。**用户发来的照片默认全部保留**，用尺寸、裁切、抠图和分组建立主次，不以审美为由自行减图。页数服从用户要求；建议拆页时先告知页数、分配和理由。

视觉语言归纳自墨奶茶公开作品，技能结构参考 Ian Xiaohei Illustrations；来源见 [sources.md](references/sources.md)。使用可迁移的设计原则，不沿用作者署名、家人、原作文字和故事。

## 按需读取

- 每次创作：读 [style-dna.md](references/style-dna.md) 和 [photo-story.md](references/photo-story.md)。
- 选版式：读 [composition-patterns.md](references/composition-patterns.md)，按当前素材决定，不固定四宫格。
- 生图/改图：读 [prompt-template.md](references/prompt-template.md)。如环境提供 `imagegen` 技能，同时遵循其工具使用规范。
- 完成检查：读 [qa-checklist.md](references/qa-checklist.md)。
- 需要比较结构或风格漂移时：查看 [版式白模](references/layout-overview.png)，结合 [sources.md](references/sources.md)；白模只说明结构，不按坐标机械复刻，真实照片须来自用户。
- 调用示例及边界情境：读 [examples.md](references/examples.md)。

## 1. 解析照片与内容

给用户照片编号 P1、P2……，用图像查看工具逐张看清；联系表只用于比较，不能代替检查原图。记录主体、动作、场景、比例、焦点、裁切保护区域，以及完整照片/抠图的适用性。区别三类信息：用户明确提供的事实；照片确实可见的内容；尚未证实的时间、地点、关系、因果和感受。

只把前两类写入成图。不能凭外貌推断关系或年龄，不能从光线、衣服或文件顺序编出“上午到晚上”。专名不确定就省略或中性描述。用户没给日期就不印日期，除非要求记录“今天”。

选一条故事线：过程、一天的片段、一次出行、一个主题或纪念节点。用户说得粗略时整理表达，不补台词或额外事件。

图片可用且用户要求制作时，解析后继续成图，不把版式、配色、文案逐项变成审批。仅在缺必要照片、人物对应关系影响制作等情况提一个简短问题。用户明确说“先分析/先写方案/先别生图”时止于方案。

## 2. 编辑成一页

先选承载情绪或主题的主图，再选场景、动作、细节图。每张照片有用途，去掉后应该损失一点信息。

- 4 张通常为 1 主图 + 2—3 辅图，或有主次的照片组；不默认四张等大。
- 3 张通常为 1 主图 + 2 细节图；少图不靠生成新场景填充。
- 同一图的完整场景与局部抠图可共用一次，关联同一来源，不伪装成多个事件。
- 默认使用全部来源照片，先建 P1—Pn 覆盖表，成图逐一核对；重复题材也可以缩为小卡片或细节图，不能自行省略。
- 如果确实建议不使用某张，制作前告知具体编号、原因及替代方案；未获得用户明确取舍时继续保留全部照片。交付时清楚列出任何经用户同意的省略。
- 超过单页可读容量时，先告知“建议几页、每页放哪些照片、为什么更合适”。用户已指定一页时保留一页方案并提出拆页选项，不直接改成多页；用户允许多页或未限定页数时，告知后可按建议执行，无须增加机械审批。

写短主题标题、每图一句局部记录、可选收尾。每图 8—22 字、一页约 60—120 字作为起点；简单素材更少，文字多则拆页。具体细节优先于通用鸡汤，保留用户口语与情绪，不一律写成亲子口吻。

按照片选版式，从照片取 1—2 个强调色，明确每段字的位置。**所有版式默认采用自由拼贴节奏**：照片大小、角度、位置和间距有变化，可局部叠放，抠图能跨照片或纸块边缘；批注利用自然空隙，不把每张照片和文字排成统一卡片。避免齐头齐尾、等距网格和整页同一倾角。版式库只提供主次与分组关系，不能照白模坐标机械套版。用户明确要规整时例外。

保留抠图与适量留白，用花字、内容相关的小贴纸、细线和局部色块增加巧思；避免整页只有统一黑字和白边照片。标题、少数关键词与正文有字形层级，小装饰不遮主体、不填满所有空白。每页主动保留一两块不放文字、贴纸、箭头或色块的连续纸面，让标题、图组或人物轮廓旁有一点呼吸空间；具体疏密见 style-dna.md。画面偏满时先减少重复装饰和过大的花字，不靠删照片或把照片缩成小缩略图来腾空间。自由叠放也要保护脸、手、关键物件和每张照片的可辨认区域。给用户一两句制作说明，含照片数量、页数及拟议取舍，不输出长篇内部分析。

## 3. 制作图片

默认用当前环境内置 `image_gen` 的图像编辑能力，以用户照片为内容输入，按 [提示词模板](references/prompt-template.md) 生成。每页单独生成；照片是单页内部素材，不是多页展示拼图。

- 逐一映射实际工具输入：`P1—Pn = 用户内容`；如附校准图，标作 `S1 = 只参考视觉语言`。
- 本地照片先查看，再用工具支持的本地引用机制传入；非本地附件用其近期图片引用机制。遵循实际工具参数，不混用引用方式。每张必要照片必须真的被包含，不能只写文件名假定模型看到了。
- 默认不把校准图送入生图，以降低串入作者人物/照片的风险；先用文字规则。需要图像校准时用最相关的一张参考，严格标清角色。
- 锁定身份、衣服、动作、物件、场景；不换脸、不重造场景、不混合五官。裁切保护脸、手部动作和叙事关键物。
- 中文逐条给出核定文本与所指照片，少而可读；不让模型补正文、日期、地点或新照片。
- 指定目标 3:4，优先约 1536×2048；无尺寸参数时写入提示词并检查实际结果，不拉伸照片凑比例。

生成式编辑不能保证原照片像素完全不变。用户要求“原图像素不变/不能重绘人脸/严格可编辑”时，改用其明确指定或接受的原图图层排版方式，只裁切、缩放、遮罩并叠加文字装饰，不能把生成图宣称为无损拼贴。此分支不具备合适工具时，交付照片映射和版式方案，明确尚未成图。普通生图请求无需额外确认技术选择。

内置图像工具不可用时说明，保留可执行提示词和方案；不把方案说成成图，不自动调用付费外部服务或索取密钥。

## 4. 检查与交付

查看实际输出，执行 [QA](references/qa-checklist.md)，对照原图检查照片覆盖、人物、文案、可读性和观看顺序。先修人物/事实错误、漏图、错字、主体遮挡，再改善主次。优先局部编辑；最多两轮针对性修复，仍有实质问题就说明限制，不无限重试。

在工作区 `output/daily-scrapbook/<主题名>/` 保存最终 `01-<主题>.png`，以及简短 `page-plan.md`：照片来源映射、事实依据、用途、版式、最终文字、实际输入次序及生图提示词、结果检查。改版用 `-v2` 等新文件名，保留用户原文件。

交付内嵌成图，简述版式与位置；只提示影响使用的实际问题。局部改稿尽量编辑既有成图，不无故重排整页。
